# Tool decision matrix

Status: research notes (2026-11-14). Evidence sources:
- **Local clone** = read-only clone in `D:/New folder (4)/upstream/<repo>` (outside the repo); SHA and
  commit date from `git rev-parse HEAD` / `git log -1 --format=%cI`.
- **GitHub API** = `https://api.github.com/repos/<owner>/<repo>` queried 2026-11-14 (`pushed_at`,
  `license.spdx_id`, `archived`). GitHub reports `NOASSERTION` when it cannot classify a licence file; in
  those cases the licence below was read from the file itself.

Decision vocabulary: **adopt now** (dependency or code in the current scope) · **adopt data only** (use the
data, not the code) · **concepts only** (re-implement ideas, copy nothing) · **defer** (credible, not in the
current contract scope) · **reject**.

GridStorm already commits to PyPSA, pandapower and Grid2Op as engines (see
[`contracts.md`](../architecture/contracts.md) §1); this matrix covers the additional candidates.

## 2. Decisions

| Tool | Original engineering value for GridStorm | Decision | Justification |
|---|---|---|---|
| PowerModels.jl | Independent AC-OPF reference implementation; PGLib baselines were produced with it. | **Defer** (reference values only) | Adds a Julia runtime that no contract environment includes and that the free Render/Vercel deployment cannot justify. Its *published* results (PGLib `BASELINE.md`) can serve as external reference numbers for cross-checks without running Julia. |
| PGLib-OPF | Licence-clean, versioned, citable small networks with published reference objectives. | **Adopt data only** | Matches the contract's `pglib-case14-ieee` network and the decision to store the raw `.m` under `data/networks/<id>/source/`. CC BY 4.0 → attribution in `dataset-manifest/1.0.license.attribution`; record tag `v23.07` / commit `dc6be4b…`. No code copied. |
| SimBench | Realistic distribution-level grids with annual profiles (useful for future distribution-level stress tests). | **Defer** (data-only candidate) | Not in the contract's initial network list. ODbL share-alike applies to derived databases: a converted SimBench network published by GridStorm must stay under ODbL and attribute SimBench. Revisit when distribution grids are in scope. |
| ANDES | Dynamic/transient stability — the physics GridStorm explicitly does not model. | **Defer** (concepts only for documentation) | No dynamic studies in the contract; no dynamic data in GridStorm datasets; GPL-3.0 means it could only be used as an isolated, separately distributed tool, never with code copied into GridStorm. GridStorm should keep stating that it performs no stability analysis. |
| PyPSA-Earth | Path to non-European networks. | **Defer** | Code is AGPL-3.0-or-later (no copying). Running the workflow is heavy and outside the current network list. Outputs it produces would need per-input licence review (OSM ODbL, etc.) before redistribution. |
| ORNL power-grid-data-factory | Mature provenance and failure-classification practices (see §3). | **Concepts only** | No licence → no code or text may be copied. HPC scale is irrelevant to GridStorm; its practices are directly relevant. |
| GOCompetition/Evaluation | Scoring logic for a different problem (SCOPF Challenge 1). | **Reject** | No licence, inactive since 2020, Python 2 era, problem formulation not used by GridStorm. |
| GOC3Benchmark.jl | Reference algorithm for multi-period AC unit commitment. | **Defer** | BSD-3 is reusable, but it is Julia, the CLI requires Gurobi (commercial — conflicts with "no paid services"), and AC-UC is outside the contract formulations (`lopf`, `ac_pf`, `n_minus_1`, `sequential`). |
| CoogGrid-Houston | Framing: critical-facility priority tiers, "with vs without" comparisons, explicit disaster scenarios. | **Concepts only** | MIT, but a hackathon project with unvalidated, hard-coded scenario multipliers; GridStorm must not inherit its numbers. The "with vs without mitigation" comparison idea is already covered by the contract's `/api/v1/comparisons`. |
| NVIDIA energy-sdk-l2rpn | UI pattern: rank candidate remedial actions by simulated max line loading before applying. | **Concepts only** | Apache-2.0 would allow reuse, but the stack (Voilà/ipyvuetify) does not fit the contract frontend (React/MapLibre), and the repo is inactive since 2022. The "simulate before recommend" rule is relevant to `gridstorm_advisor`. |
| Grid2Game | Human-in-the-loop stepping of Grid2Op episodes. | **Concepts only** | MPL-2.0 (file-level copyleft — any copied file must stay MPL-2.0 with its header); Dash UI does not fit the React frontend; "early alpha" and inactive since 2022. Episode replay UX may inform the `/operations` route. |

## 3. ORNL power-grid-data-factory practices

Source: [`README.md`](https://github.com/ORNL/power-grid-data-factory/blob/a7bd2c9622a3e60cbabc469c2a33591b8a65c997/README.md),
[`docs/reproducibility.md`](https://github.com/ORNL/power-grid-data-factory/blob/a7bd2c9622a3e60cbabc469c2a33591b8a65c997/docs/reproducibility.md),
[`docs/schema_contracts.md`](https://github.com/ORNL/power-grid-data-factory/blob/a7bd2c9622a3e60cbabc469c2a33591b8a65c997/docs/schema_contracts.md),
[`docs/data_generation_capabilities.md`](https://github.com/ORNL/power-grid-data-factory/blob/a7bd2c9622a3e60cbabc469c2a33591b8a65c997/docs/data_generation_capabilities.md)
at commit `a7bd2c96…`. Summarised in our own words (no licence → nothing copied).

| Practice (ORNL) | What it is | GridStorm status |
|---|---|---|
| Provenance per attempt | Each attempt stores immutable resolved inputs, full stdout/stderr, raw solver outputs, intermediates, normalised outputs and validation artefacts separately. | **Adopted in reduced form by the contract**: `execution-manifest/1.0` (scenario hash, dataset sha256, engine/solver versions + options, platform, timestamps, result sha256, git sha) and the `gridstorm-artifact/1.0` header (command, input paths + sha256, platform, payload sha256). Full stdout/raw-output preservation is not in the contract. |
| Manifests + checksums | `manifests/artifacts_manifest.json` and `checksums.sha256` per attempt; integrity and archive verification scripts. | **Adopted**: `dataset-manifest/1.0.files[].sha256`, artifact `payload_sha256` over canonical JSON. |
| Deterministic execution | Hash-based, process-independent seeds (e.g. a per-variant seed derived from SHA-256 over case id, base seed and variant index), deterministic run paths and contingency slugs. | **Adopted in principle**: `execution.deterministic`, `execution.seed`, `scenario_hash` over canonical JSON, deterministic solver options (`threads: 1`). Hash-derived sub-seeds are not specified in the contract. |
| Failed-run classification | Exactly one terminal marker per attempt: `SUCCESS, FAILED, TIMEOUT, CANCELED, NODE_FAILURE, INFEASIBLE, NONCONVERGENT, INVALID_INPUT, ISLANDED, SOLVER_SUCCESS_PRESERVATION_FAILED`; failed and non-convergent runs are preserved. | **Adopted as two axes**: Job `status` (infrastructure: `queued/running/completed/failed/cancelled/timeout`) separate from scientific `outcome` (`feasible/infeasible/error`) plus solver `termination_condition`; infeasible results are returned with empty series, never filled. The contract has no `islanded`/`nonconvergent` outcome values; adding them to AC/N-1 artifacts is a proposal only, not part of the contract. |
| Explicit approximation labels | DC outputs flagged `physical_fidelity: dc_approximation`. | **Adopted**: result `assumptions` (e.g. "DC linearised power flow (LOPF) — no reactive power, voltage magnitudes or losses") and `provenance` classes. |
| Append-only registries, never overwrite | Immutable `attempt_<index>` directories, append-only run registry, versioned derived artefacts. | **Partially**: the contract persists a job table and allows reuse of results for identical scenario hash (flagged `reused: true`); immutable attempt directories are not specified. |
| Schema compatibility rules | Additive changes preferred; renames only with migration notes; evolution log. | **Adopted**: versioned schema strings (`*/1.0`), contract changes via `docs/decisions/`. |
| DC as screening, not a gate | DC results are screening features; screening rejects are audited with stratified AC samples. | **Concept adopted for `stormbench`**: PTDF/LODF screening must be scored against AC N-1 results (pandapower), including the misses, rather than trusted as a filter. |
| HPC campaigns, Slurm/Lustre, billion-sample sweeps | — | **Not adopted** (out of scope). |
